A staged reading list for anyone learning software testing, from the basics to TDD and quality assurance. Each pick has its own review on this blog, and every entry links to it. The order follows a learning path: fundamentals, then practice, improvement, and a body of knowledge.

## Why learn software testing

Tests act as a safety net that lets you keep changing code without fear. Master the techniques and viewpoints, and you leave blind manual testing behind. Building in quality helps every engineer who writes code.

## 1. Get started with testing

### Learning Software Testing Techniques for the First Time

A gentle introduction to core techniques like equivalence partitioning and boundary values. It builds a base for what to check and how. I cover it in the [review](/posts/introduction-software-testing/).

### The Software Testing Textbook

A broad, systematic tour of testing ideas and techniques. It suits anyone who wants the big picture. My notes are in the [review](/posts/software-testing-textbook/).

## 2. Pick up TDD and unit testing

### Test-Driven Development

A classic that teaches TDD by writing tests first and driving design. You pick up the rhythm by doing. I wrote it up in the [review](/posts/test-driven-development/).

### Unit Testing: Principles, Practices, and Patterns

It sorts out what makes a good unit test through value and maintainability. It guides you toward tests that mean something and resist breakage. I dig into it in the [review](/posts/unit-testing-concepts-usage/).

## 3. Practice and improve in the field

### 50 Ideas to Improve Your Software Testing

Fifty concrete ideas for rethinking how you test. It helps when your current approach feels stuck. See the [review](/posts/software-testing-improvement-ideas/).

### Web API Testing Techniques

Practical viewpoints and methods aimed at testing Web APIs. It raises the quality of API development. I cover it in the [review](/posts/web-api-testing-techniques/).

## 4. See quality as a whole

### SQuBOK Guide V3

A reference that organizes the software quality body of knowledge. It places testing inside the wider picture of quality assurance. I wrote about it in the [review](/posts/squbok-guide-v3/).

## Wrap-up

Start with the two primers, then sharpen your writing with TDD and unit testing. Reach for improvement ideas and the quality body of knowledge when you need them. Every book has a full review here, so start with whichever one interests you most.
