I read [Microservices Patterns](https://amzn.to/4dOZjFp).

This book by Chris Richardson systematically organizes the design patterns of microservices. Starting from decomposition strategies, it covers a wide range of challenges and their established solutions—distributed transactions with Sagas, API Composition, CQRS, event sourcing, inter-service communication, testing, and deployment.

What I like is that each pattern addresses "what problem it solves" and "what trade-offs it carries." Rather than presenting patterns as silver bullets, it discusses the context of application together with the costs, which makes it a solid reference when making decisions in practice.

The samples are Java-based, but the patterns themselves are language-agnostic, so developers working in other languages can read across easily. Reading it alongside a book on microservices architecture deepens understanding from both the conceptual and implementation sides.

If you are considering or operating microservices, this is a classic worth keeping close at hand.
