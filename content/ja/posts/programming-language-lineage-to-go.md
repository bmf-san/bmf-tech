# 概要

プログラミング言語の歴史には、大きく2つの系譜がある。1つはニクラウス・ヴィルトがPascalから磨き上げた「構造とモジュール化」の系譜、もう1つはトニー・ホアのCSPに始まる「並行処理」の系譜である。この2つの大河は長い時間をかけて交差し、最終的にGo言語へと合流した。

本記事では、Algol 60からGoに至るまでの言語をたどり、それぞれの特徴と歴史的なつながりを整理する。

# 2つの大きな系譜

先に全体像を示す。Goは、次の2つの流れが1つに合わさった言語である。

- Oberon系: シンプルな型システム、継承のないオブジェクト指向、パッケージによるモジュール管理、ガベージコレクション
- CSP/Alef系: チャネルによるプロセス間通信、`select`構文、軽量スレッド

Goは、C言語のシンプルな構文を土台にしつつ、Oberonの「無駄のない型システム」とNewsqueakやAlefの「CSPによる並行処理」を融合させた。そして、Alefが抱えたメモリ管理の難しさを、モダンなランタイムで解決して生まれた言語である。

# 1. Algol 60の系譜：構造化プログラミングの原点

## Algol 60（1960年）

現代のほぼすべての手続き型言語は、Algol 60を直系の祖先に持つ。

`begin ... end`によるブロック構造、ローカル変数のスコープ、再帰呼び出し、そしてBNF記法による文法定義を、世界で初めて導入した言語である。C、Pascal、Java、Goに至るまで、構文の基本ルールはここから始まっている。

## Pascal（1970年）

Pascalは、ニクラウス・ヴィルトが教育用およびシステム記述用として設計した言語である。

Algol 60をよりシンプルにし、`record`型に代表される厳格な型システムを導入した。コンパイル速度が非常に速いことでも知られる。構造化プログラミングを世界へ広め、C言語と並ぶ標準的な言語になった。

# 2. モジュール化とOberonの系譜：ヴィルトの探求

ここからは、ヴィルトが「ソフトウェアの複雑化」に抗い、シンプルさとモジュール化を追求した歴史である。

## Modula-2（1978年）

Modula-2はPascalの後継であり、その名のとおり「モジュール（Module）」の概念を導入した。

定義部（`DEFINITION MODULE`）と実装部（`IMPLEMENTATION MODULE`）を分離し、分割コンパイルとカプセル化を可能にした。コルーチンによる簡易な並行処理もサポートしている。

## Oberon（1987年）

Oberonは、Modula-2を極限まで削ぎ落とし、超軽量OS（Oberon OS）とともに作られた言語である。

複雑な機能を排除し、単一継承に似た「型拡張（Type Extension）」と、ガベージコレクションだけを新たに加えた。「最小限の機能で最大の表現力を得る」という、ヴィルトの哲学が到達した1つの答えである。

## Object Oberon（1989年）／Oberon-2（1991年）

Oberonに本格的なオブジェクト指向を加え、洗練させた拡張版がこの2つである。レシーバを持つ型バインド手続き、すなわちメソッドを導入した。

特徴的なのは、`class`構文を新設しなかった点である。Oberonの「型拡張」に対して、メソッドを直接関連付ける方式を採用した。

### Goとのつながり

Goの設計には、OberonとOberon-2の影響がはっきりと表れている。

- `class`を持たず、構造体にメソッドをバインドする
- 継承ではなく、型の埋め込み（embedding）を使う
- パッケージによってモジュールを管理する

これらはいずれも、Oberon系から受け継いだ考え方である。

# 3. CSPと並行処理の系譜：Goの並行処理の祖先

Go最大の特徴であるゴルーチンとチャネルは、ベル研究所を中心とする並行処理モデルの系譜から生まれた。

## CSP（1978年）

CSP（Communicating Sequential Processes）は、トニー・ホアが提唱した並行処理の理論・モデルである。言語そのものではなく、概念である点に注意したい。

CSPは「メモリを共有して通信する」のではなく、「通信することによってメモリを共有する」という思想を打ち立てた。スレッドとロックではなく、プロセスとチャネルで並行処理を捉える発想である。

## Squeak（1985年）

Squeakは、ベル研究所のルカ・カルデリとロブ・パイクが開発した言語である。画面UI、すなわちウィンドウシステムの並行処理を記述するために作られた。

CSPモデルをプログラミング言語として実装した、初期の実験例である。なお、Smalltalk実装のSqueakとは同名の別物である。

## Newsqueak（1988年）

Newsqueakは、ロブ・パイクがSqueakをもとに開発した、より実用的な並行処理言語である。

構文はOberonやCに近い。ファーストクラスのチャネル（`chan`）と、非同期処理を扱う`select`構文が、初めて明確な形で実装された。

## Alef（1995年）

Alefは、ベル研究所の次世代OSプロジェクトPlan 9のために開発されたシステムプログラミング言語である。フィル・ウィンターボトムやロブ・パイクが開発に関わった。

C言語風の構文に、NewsqueakのCSP型並行処理（`proc`、`task`、`chan`）とOberon風の型システム、そしてガベージコレクションを統合した意欲的な言語である。しかし、C言語のようなポインタ操作とGCの相性の悪さや、エラー処理の難しさから、Alefは普及しなかった。

この失敗の経験が、のちのGoの設計を支えることになる。

# まとめ：すべての系譜はGoへ

ここまで見てきた言語は、Goの設計者たちがGoを作るまでに通過し、洗練させてきた技術の系譜である。ロブ・パイクやケン・トンプソンらが歩んだ道のりそのものといえる。

```
【Algol 60】
   │
   ├─►【Pascal】─►【Modula-2】─►【Oberon / Oberon-2】
   │                                  │ (型システム・構造体メソッド・GC)
   │                                  ▼
   │                             ┌──────────┐
   │                             │  Go 言語  │
   │                             └──────────┘
   │                                  ▲
   ├─►【C言語】                       │ (CSP型並行処理: goroutine / channel)
   │     │                            │
   └─────┴─►【CSP】─►【Newsqueak】─►【Alef】
```

Goは、Oberon系から「無駄のない型システムとモジュール管理」を、CSP/Alef系から「チャネルによる並行処理」を受け継いだ。そして、C言語のシンプルな構文を土台に、Alefが実現できなかったメモリ管理を、モダンなランタイムで解決した。

普段何気なく書いているGoの1行の背後には、半世紀を超える言語設計の積み重ねがある。その系譜を知ると、Goというデザインに込められた意図が、より深く見えてくる。
